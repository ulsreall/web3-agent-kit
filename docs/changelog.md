## [Unreleased]

### Fixed
- **docs:** the site was serving stale numbers and a missing document. The risk
  register lived at the repo root, outside `docs_dir`, so `/risks/` returned 404
  while three pages linked to a GitHub blob instead. The version stamps on the
  home page, versioning policy, security model, README banner and its SVG still
  read v1.19.1 after the 1.19.2 release, and the headline figures (tests,
  coverage, routes) had not moved since 1.18. `tests/test_docs_sync.py` now pins
  every stamp to `__version__` and makes the three surfaces agree, so a release
  that forgets the docs fails CI instead of shipping.
- **api:** `resolve_token` accepted any `0x`-prefixed 42-character string, so a
  typo (`0x` + 40 `z`) was taken as an address and only failed inside web3 once
  the request had been accepted. It must match 20 hex bytes now, and an
  address-shaped non-hex value gets its own message.
- **oracle:** the "weighted median" was the upper-middle element, so with two
  sources a single high outlier always set the price (100/300 returned 300). It
  averages the two middles now. `get_prices_batch` also dropped the whole batch
  when one token had no quote; that token is left out instead.
- **airdrop:** the multi-wallet farmer never recorded what it had done. Completed
  tasks were skipped without being counted, so a finished campaign logged "0
  tasks, 0 points" and `get_total_points()` stayed at zero; the per-wallet
  progress it built was never persisted. The daily task counter was also never
  incremented, so `max_tasks_per_wallet_per_day` could never bite. All fixed, and
  `farm_campaign` now delegates to its identical twin `async_farm_campaign`.
- **airdrop:** the legacy Zealy client lost the whole quest list when one quest
  had a null `type` (`.lower()` raised inside the wrapper) and crashed the sum on
  a string `xp`; a null leaderboard `rank`/`username` came through raw. All are
  coerced or defaulted. The legacy Gleam and Zealy `complete_task` docstrings now
  say they mark the task locally instead of submitting — `GleamExecutor` and
  `ZealyExecutor` are the ones that post.
- **airdrop:** a Google Form question with neither an input nor a listbox (a
  text-only prompt or a grid item) counted for nothing, so `fields_filled +
  fields_skipped` never added up to `fields_found` and the skipped items were
  invisible in `details`.
- **prices:** a failed lookup discarded an expired-but-real price and returned the
  caller's fallback, so a feed blip zeroed positions that had a known value
  seconds earlier. The stale price is served with a warning now, and an unknown
  asset falls through to the fallback as before.
- **airdrop (legacy base):** the sync *and* async request helpers had the two
  defects already fixed in the executor helper — a persistent 429 ended in
  `raise None` (a `TypeError`), and `Retry-After` went straight into `int()`.
  `parse_retry_after` moved to `web3_agent_kit/utils/retry.py` so both helpers
  share one implementation instead of drifting apart.
- **airdrop:** the plugin registry picked "the first `BasePlatformExecutor`
  subclass in the module", but `dir()` is alphabetical and includes names the
  module only imported — so a helper class or a re-export could be registered
  under a platform name. The class whose `platform_name` matches the module is
  preferred now. Separately, a user plugin that forgot `platform_name` inherited
  `"unknown"` from the base class and overwrote the previous plugin; it falls
  back to its class name.
- **tests:** the rehearsal runner test failed intermittently on a loaded CI shard.
  The sheet pins a per-second `evaluatedAt` that the policy commitment binds, but
  the gate was evaluated with a fresh clock, so a second rolling over mid-attempt
  produced a spurious "covers another policy decision" and, once the retries were
  spent, a bare `ERROR`. One second is pinned per attempt now and used on both
  sides; the assertion also prints the runner's error detail instead of only the
  outcome.
- **airdrop:** session cookies were written with a plain `open()` in six places
  across the three social executors, so a crash mid-write left a truncated
  `cookies.json` and the next run could only report the session as unreadable.
  One shared writer now writes to a temp file and `os.replace`s it, and the
  readers use `read_text` with an explicit encoding.
- **airdrop:** Port3 had the same null `type`/`title`/task-list holes as its
  siblings, so a task the API sent with a null type disappeared.
- **airdrop:** TaskOn had the same null `type`/`title`/task-list holes, plus a
  null campaign name that raised inside `visit`.
- **airdrop:** QuestN dropped any task with a null `type` or `title`, and a null
  `tasks` list crashed `get_tasks`; a null quiz `questions` value did the same to
  quiz handling. All fall back now.
- **airdrop:** Layer3 lost every step whose `type` or `title` was null, and while
  `steps`/`tasks` with a null value crashed `get_tasks` with a `TypeError` on
  `len()` (a null `data` envelope did the same to `get_quests`). All fall back
  now; the CAPTCHA solver is cached instead of rebuilt per step.
- **airdrop:** an Intract task whose `type` or `title` was `null` (present, not
  absent) threw on `.lower()` and was dropped from the campaign entirely — the
  same class of hole fixed across the other parsers. Both fall back now, and the
  CAPTCHA solver is cached per instance instead of rebuilt for every task.
- **airdrop:** Galxe's CAPTCHA hook built a solver, discarded it and always
  returned `None` — so `captcha` was never attached to a task completion or a
  claim, and an unknown `captcha_provider` was swallowed at debug level, which
  looks exactly like a campaign that needs no CAPTCHA. The solver is now built
  once and cached, an unusable provider logs a warning, and `close()` drops it.
- **airdrop:** the shared request helper raised `TypeError` when a platform kept
  answering 429. Every attempt was a rate-limit response, `last_error` was never
  assigned, and the loop ended in `raise None`. It now raises an `HTTPError`
  carrying the last response. The same helper also fed `Retry-After` straight to
  `int()`, so the RFC's HTTP-date form (and any non-numeric header) escaped the
  retry loop as a `ValueError`; headers are parsed defensively and a huge or past
  value falls back to the configured delay, capped at 300s. A 429 on the final
  attempt no longer sleeps before giving up.
- **docs:** the root `REVIEW.md` is now `docs/review-findings.md` and is published
  with a closed-item table; the PoCs moved next to it and both print zero GAPs
  again (case C re-submitted a rebuilt request and C2 forgot the store it consumed
  in, so both had stopped proving anything). The changelog role split is stated in
  both files and in `CONTRIBUTING.md`.
- **airdrop:** the Zealy visit-quest handler had the same orphaned tab as the
  Gleam one — the close now runs in a `finally`.
- **airdrop:** the Gleam visit handler opened a tab, navigated and closed it,
  but the close was not in a `finally` — a navigation that raised left the tab
  open on every retry-exhausted visit.
- **airdrop:** every platform scanner built its campaign id with
  `str(item.get("id", ""))`, so a missing id produced `""` (all such entries
  collided in the dedupe index) and a `null` id produced `"None"`. Entries
  without a usable id are skipped now.
- **airdrop:** scanner `points` and `participant_count` were passed through
  raw, so a string `"50"` raised `TypeError` in the numeric filters
  (`"50" < 10`); both are coerced. A `null` title becomes "Untitled" and
  `null` tags become an empty list.
- **bridge:** a route whose `toAmount`, `gasCostUSD` or `duration` came back
  `null` raised on `int()`/`float()` and discarded **every** route from that
  provider, not just the bad one — Li.Fi being one API call, the whole batch
  went with it. Numbers now go through `coerce_int`/`coerce_float` in a shared
  `web3_agent_kit.coerce` module.
- **airdrop:** a task whose `points` field arrives as `""` or `null` was dropped
  entirely by the Galxe and Layer3 parsers — `int("")` raises and the bare
  `except` returned `None`, losing the whole task. Shared `coerce_int` helper
  defaults to 0. A `null` task id no longer becomes the string `"None"`.
- **airdrop:** the Galxe HARD difficulty branch was unreachable, because
  `on_chain_bridge` starts with `on_chain` and the `elif` never ran.
- **airdrop:** the faucet claimer reported `{"success": false, "error": "quota"}`
  as a success — the fallback was a substring match on `str(data)` and the word
  "success" is in the payload. An explicit `success` flag now wins; the
  substring match only applies when there is no flag and no JSON body.
- **airdrop:** a failed claim still carried the faucet's nominal amount, and a
  plain-text 200 was unconditionally counted as a success. The amount is now
  only set once the faucet confirms, and a text body is matched against its
  configured success indicator.
- **airdrop:** a cooldown file written without a timezone offset crashed the
  comparison (`naive` vs `aware`); a naive timestamp is now read as UTC.
- **airdrop:** `claim_all` and `async_claim_all` were byte-identical copies;
  `claim_all` delegates.
- **airdrop:** campaign discovery wrote its seen list to `save_path` but read it
  back from a separate `seen_path`, so configuring only a save path meant the
  file was rewritten every run and never loaded — nothing was deduplicated
  across runs. `seen_path` now falls back to `save_path`.
- **airdrop:** a Galxe campaign with `"id": null` was stored under the campaign
  id `"None"`, because `str(None)` is truthy; the raw value is checked first.
  A campaign without an id is also skipped when discovering, instead of raising
  `KeyError` and losing the whole batch.
- **airdrop:** the CAPTCHA solver posted to 2captcha over plain `http://` while
  the API key travels in the request body; now `https://`.
- **airdrop:** `WLGrinder.apply_bulk` and `async_apply_bulk` were byte-identical
  copies (both async, both awaiting the sleep); `apply_bulk` now delegates so
  the two cannot drift.
- **airdrop:** `TelegramExecutor.join_channel` returns `True` for a page it only
  opened, so "joined" and "merely visited" are indistinguishable to a caller.
  The docstring now says so instead of claiming a join.
- **airdrop:** Zealy quest classification returns the empty community slug for a
  bare `https://zealy.io` URL (`parts[-1]` was `""`, which is not falsy enough);
  and Gleam only recognised a Twitter follow when the word "twitter" appeared,
  so the current "Follow on X" wording fell through to the generic handler and
  never opened the tab.
- **airdrop:** all three form fillers returned early on the most common failure
  ("no form fields detected") without calling `browser.close()`, leaving a
  chromium process (and its profile lock) behind on every attempt. The body is
  now wrapped in `try/finally`.
- **airdrop:** the on-chain farmer's own `Chain` enum says `bnb` (and offers
  `zksync`, `scroll`, `linea`, `blast`), while the gate's says `bsc` and knows no
  envelope for the rest. `_resolve_chain` looked the name up directly and fell
  back to Ethereum on `ValueError`, so a `chain="bnb"` farm sent a 56-chainId
  transaction to a gate told to expect Mainnet and every write was refused.
  Aliases are mapped and an unknown chain now raises instead of being guessed.
  `farm_all` delegates to `async_farm_all`, which it duplicated.
- **security:** the token parsers fed API strings straight into `float()`/`int()`.
  GoPlus fills an unmeasured field with `""`, so one empty `buy_tax` aborted the
  whole quick check and threw away the honeypot verdict that had already been
  read; the same happened to liquidity, holder count and holder percentages.
  A shared `_parse_float`/`_parse_int` treats `""` and `None` as unknown-and-zero
  so the rest of the record survives, and `quick_check` no longer reports a
  honeypot with an empty tax as `unknown` plus an error.
- **chains:** `ChainManager.get_solana()` imported `solana.rpc.api.Client`, which
  solana-py 0.42 removed when it went async-only — under the declared
  `solana>=0.35` range a fresh install raised `ModuleNotFoundError`. It now uses
  the sync client when present and the async client otherwise. The module also
  gained tests: default RPC schemes, chain-id coverage, unconfigured-chain and
  non-EVM errors, and the client fallback.
- **execution:** consumed authorizations are tracked by a replay store instead of
  a per-gate set. The default is process-wide in-memory; `WEB3_REPLAY_DB` selects
  a durable SQLite store so a restart or a second worker cannot replay an
  authorization. Expired keys are pruned on consume and a broken store fails
  closed.
- **api:** every write route called the library with the wrong shape and could never reach a
  signature. `POST /swap/execute` passed a chain name where a `ChainManager` was expected, a
  float where a `Chain` was expected, and never resolved symbol tokens; `POST /bridge/execute`
  built `BridgeAgent` without a wallet and rotated every `transfer()` argument;
  `POST /dca/create` built `DCABot` without a manager and used five keyword names that do not
  exist. Routes now share `api/deps.py`, and `tests/test_api_contracts.py` binds each call
  against the real signature so the drift cannot return silently.
- **api:** write routes build a gate-bound wallet when `WEB3_AUTO_AUTHORIZE=true`, so they can
  actually sign. Unset still fails closed.
- **api:** the read routes had the same drift. Approval scan/revoke, gas estimate, the watcher,
  the yield optimizer and `/wallet/info` all passed a chain name where a `ChainManager` was
  expected and 400'd on the first call; `gas.estimate()` also needs a target address and
  `yield.find_best()` needs an asset and an amount. All of them now go through `deps`.
- **defi:** the aggregator defined its own `Chain` enum, so passing the library's `Chain` raised
  `KeyError` on every chain-id lookup. It re-exports the real enum now.
- **defi:** Paraswap decimals were hardcoded to 18, which the API rejects with "Source Decimals
  Mismatch" for every 6-decimal token. Decimals are resolved by the quote and carried through.
- **defi:** 0x sent the 1inch key in its `0x-api-key` header; `zeroex_api_key` and
  `AggregatorConfig.from_env()` replace the guesswork.
- **dca:** `_execute_swap` called `uniswap.swap()`, which does not exist (it is `execute()`), and
  read the result as a dict although it is a `SwapResult`. Every DCA buy failed silently. The API
  also wires a Uniswap instance in, so executions are real instead of the demo branch, and
  `POST /dca/orders/{id}/execute` runs one buy now.
- **wallet:** `send_transaction` fills `from`/`nonce`/`chainId`/gas/fees when the caller omits
  them, instead of handing the gate an incomplete transaction.
- **wallet:** `MultiWalletManager` called `send()`, `transfer_token()` and `get_balance()` (as a
  dict); none existed. They do now, and all of them route through `send_transaction`.
- **chains:** the default Ethereum RPC (`eth.llamarpc.com`) answers HTTP 525 and the default
  Polygon RPC (`polygon-rpc.com`) answers "API key disabled", so every read on those chains failed
  out of the box. Both point at publicnode now, along with the copies in the per-module examples.
- **bridge:** the Li.Fi path fell back to chain id 1 for any chain missing from `CHAIN_IDS`,
  signing a Base transaction as Ethereum.
- **execution:** contract creation (`to=None`) is enforced instead of refused. The request
  object no longer requires `to`, and the intent layer carries an explicit creation profile
  that requires init code and forbids a destination.
- **execution:** calldata is resolved from `data` or its `input` alias, with a conflict treated
  as a denial. Previously an `input`-only transaction hashed empty calldata while the signer
  rejected the key outright.
- **execution:** the authorization evidence's policy commitment is now compared to the
  evaluated verdict; a mismatched commitment is a denial.
- **tests:** the suite no longer depends on ambient environment. `tests/conftest.py` sets a
  deterministic `PRIVATE_KEY`/`WEB3_API_KEY`, so the integration module runs instead of
  silently skipping, and `test_solana_lp.py` skips cleanly without the `solana` extra.
- **solana:** `send_token` creates the sender's associated token account idempotently and reads
  the mint's owner to pick the token program, so Token-2022 mints derive the right accounts.

### Added
- Tests for the parts of the gate nothing exercised: every envelope
  canonicalizer branch (bool/negative/garbage integers, malformed and
  non-string addresses, calldata aliases, creation profiles, fee-field
  mixing), `AuthorizationEvidence` validation and freshness, gate and request
  construction failures, and a provider that returns the wrong type.
  `execution/envelope.py` is at 100% line coverage, `interceptor.py` 99%.
- `Wallet.raw_signer`, so a gate can be built around a wallet without touching a private
  attribute.
- `Wallet.send`, `Wallet.transfer_token`, `Wallet.get_balance_summary`.
- `web3_agent_kit.execution.replay` with `InMemoryReplayStore` / `SqliteReplayStore`.
- `POST /dca/orders/{id}/execute`.

## [1.19.0] - 2026-10-25

### Features
- **p1:** gate-exercise mode, live trust root from materials, and PEM field tolerance,
  so the verdict gate can be exercised against real material rather than fixtures alone.
- **p1:** the Insight verdict gate now runs in the live path (verdict-gate spec v0.1,
  `policy-decision` v1 half).
- **report:** the acceptance report records the explicit outcome of both PriorSeal gate
  checks instead of leaving a pass implicit.

### Fixed
- **p1:** the verdict gate refuses unless the attestations hash to the bound pair, and a
  missing insight drop refuses rather than skipping the gate. The `policy-decision` v1
  field set (verdict-gate spec v1.0 §3) is enforced. A missing drop reports
  `MATERIALS_MISSING` per verdict-gate spec v0.3 §4.
- **execution:** PriorSeal authorization is validated against the pinned sheet rather than
  recomputed live, so a drifted tree cannot authorize a broadcast.
- **cli:** `wak --version` reads `__version__` instead of a hardcoded literal. The literal
  drifted from the package on every release and failed `test_version` on all four Python
  versions; a release now needs only the single bump release-please already makes.

### Build
- `requirements-lock.txt` is regenerated with `pip-compile --generate-hashes` (54 pins,
  transitive included). It previously aborted under `--require-hashes` because `py-ecc`
  was unpinned.
- The lock no longer pins `--index-url`/`--trusted-host` to a Tencent mirror that only
  resolves inside a Chinese network, which broke every install from CI or a clean machine.
- `multidict` 7.0.0 and `aiohttp` 3.14.3 were unsatisfiable together; the lock now holds
  `aiohttp` 3.14.5 with `multidict` 7.2.0.
- `pytest-timeout` joined the `dev` extra, so the `--timeout` flag CI passes always
  resolves.
- The `pkg_resources` fallback in the plugin registry is gone; entry points come from
  `importlib.metadata` only.

### CI
- A dedicated `lint` job runs `ruff check` and `ruff format --check`; the tree is formatted
  and lint-clean (18 findings and 182 unformatted files at the start of this cycle).
- `pip-audit` audits `requirements-lock.txt` rather than the runner image, so a preinstalled
  `setuptools` cannot fail the build.
- The test matrix covers 3.10 through 3.13.
- DCO skips bot-authored commits: release-please opens its version bump from `GITHUB_TOKEN`
  as `github-actions[bot]`, and a bot cannot attach a personal `Signed-off-by`. Every human
  commit is still checked.
- Dependabot groups minor and patch bumps into a single PR and keeps majors separate.

### Documentation
- The headline test and coverage numbers were corrected on the banner, the README and the
  docs home page. They had drifted to 1,971 tests and 75% coverage against an actual
  1,832 passed / 171 skipped at 71%.

## [1.18.4] - 2026-09-19

### Fixed
- The static signer-surface check no longer misses violations when the scanned
  package sits under a directory named `venv`, `.venv`, `build` or `dist`.
  Exclusions were evaluated against the absolute path, so such an ancestor
  excluded the entire scan: the checker reported zero signer calls and exited 0
  while an unapproved call was present. Exclusions are now relative to the scan
  root, so ancestors cannot suppress the scan while nested environment
  directories remain excluded.

  This affected the most common way to run the check — from inside a
  virtualenv. CI did not catch it because the runner checks out to a path with
  no excluded ancestor.

### Added
- Regression tests parametrised over five ancestor names and four nested
  directory names, plus the missing empty-stderr assertion on the checker
  module test.

## [1.18.1] - 2026-09-18

### Fixed
- **execution:** three pre-sign gate gaps that allowed signing without the
  policy being fully applied. A chain mismatch between the evaluated chain and
  the transaction's `chainId` was not detected; an unbound wallet signed
  contract creation (`to=None`); and a policy allow produced a signature with
  no principal exact-call authorization. Each is reproducible with
  `tools/p0_probe.py` against the previous revision.
- The CLI version pin is now covered by a test. It is hardcoded separately from
  `pyproject.toml` and `__version__`, and had drifted two minor versions behind
  without anything failing.

### Added
- `CallEnvelopeV1` (`agent-call-envelope.v1`) as a canonical, versioned call
  identity, with the policy verdict kept in a separate domain-separated
  commitment so "policy allowed" and "the principal authorized this exact call"
  remain independently verifiable.
- `AuthorizationProvider` protocol and `NullAuthorizationProvider`. Policy allow
  is no longer sufficient to sign.
- `tools/p0_probe.py`, which reproduces the enforcement findings against any
  revision.

### Changed
- `airdrop`, `messaging` and `governance` accept an injected policy,
  authorization provider and preconfigured gate. Governance previously built a
  fresh gate per call, resetting its authorization sequence and replay set.

### Breaking
- `PreSignInterceptor` requires an authorization provider for any signature.
- `allow_unattended` is removed; confirmation is UX and cannot substitute for
  authorization.
- Transactions must carry `from`; the envelope needs an executor to have an
  identity.
- `AuthorizationRequest.call_fingerprint` changed value. It is now the canonical
  envelope digest: the action label is excluded, the executor is included.

## [1.18.0] - 2026-09-18

### Features
- **execution:** enforced pre-sign authorization gate. Every write-capable
  module now signs through a single approved API that evaluates the execution
  policy before any signature is produced. A missing policy is fail-closed, a
  confirmation-required policy refuses to sign unattended, and every
  evaluation is recorded in an append-only audit log with the authorized call
  fingerprint.
- Added `PreSignInterceptor` and `Wallet.bind_enforcement()`. A wallet with no
  bound gate refuses to sign write-capable transactions.
- Migrated the airdrop, messaging, governance, bridge and restaking signing
  paths behind the gate, including the three that previously bypassed the
  Wallet wrapper.
- Added `tools/check_signing_surface.py`, enforced in CI, which fails on any
  new unapproved direct signer call.

### Security
- `ExecutionPolicy` is now exported and enforced on the signing path. It was
  previously unreachable from the modules that build transactions.

### Breaking
- Modules that previously signed without a policy now raise
  `EnforcementDenied`. `messaging`, `governance` and airdrop accept an optional
  `policy=` argument; when omitted, they deny rather than sign unprotected.

### Dependencies
